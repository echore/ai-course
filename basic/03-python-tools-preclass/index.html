02 · Create files · ~7 minutes

Create your project files

sample_data.jsonFictional candidate and job data

A. Copy the fictional sample data

Open sample_data.json. Copy and paste this entire example, then save it.

sample_data.json
{
  "candidate_name": "Alex",
  "candidate_skills": ["python", "Excel", "Communication"],
  "job_title": "Junior Data Analyst",
  "required_skills": ["Python", "SQL", "Excel"]
}

B. Copy the starter Python script

Open resume_analyzer.py. Paste the following code and save it. You do not need to write the logic from memory — we'll build and explain it together in the live class.

resume_analyzer.py
# Mini Resume Analyzer — Week 3 pre-class
# Uses fictional skills; this is rule-based, not AI.

import json
from pathlib import Path

# Load data from a JSON file next to this script.
data_file = Path(__file__).resolve().parent / "sample_data.json"
with data_file.open("r", encoding="utf-8") as file:
    data = json.load(file)

candidate_name = data["candidate_name"]
candidate_skills = data["candidate_skills"]
required_skills = data["required_skills"]

# A function for comparing skill names, ignoring capitalization.
def check_skill(skill, listed_skills):
    for listed_skill in listed_skills:
        if skill.lower() == listed_skill.lower():
            return True
    return False

print("=== MINI RESUME ANALYZER ===")
print("Candidate:", candidate_name)

# Loop through the job's required skills.
for skill in required_skills:
    if check_skill(skill, candidate_skills):
        print(skill, ": Listed")
    else:
        print(skill, ": Not listed")

Why two files? JSON stores the input data; Python contains the instructions. You can change data without rewriting the program. The Python file uses built-in libraries, so no extra packages are required.

03 · Run & observe · ~4 minutes

Run your analyzer

Return to the VS Code terminal. Make sure the terminal is inside your project folder. Run the appropriate command:

Mac
python3 resume_analyzer.py
Windows
py resume_analyzer.py

Expected output

Terminal output
=== MINI RESUME ANALYZER ===
Candidate: Alex
Python : Listed
SQL : Not listed
Excel : Listed

Stop and think: The loop examines job requirements; the function checks whether each requirement appears in the candidate's listed skills.

04 · Predict, change & test · ~5 minutes

Change the input — not the Python

First predict: If you add "SQL" to the candidate's skills, what should happen to the SQL result?

Now open sample_data.json and make just two edits:

  1. Change "candidate_name" from "Alex" to "Jordan".
  2. Add "SQL" as an additional item in "candidate_skills". Remember the comma separating list items.
  3. Save JSON and run the same Python command again.
Expected changed output
=== MINI RESUME ANALYZER ===
Candidate: Jordan
Python : Listed
SQL : Listed
Excel : Listed

Notice that "python" in lowercase still matches the requirement "Python" because our function uses .lower(). This is still an exact skill-label check after lowercasing, not an assessment of skill proficiency.

05 · Debug & explain · ~5 minutes

If something breaks, inspect the evidence

In our course pilot, the script initially failed because it couldn't locate sample_data.json. This is a useful example of debugging: an error message often tells you which assumption failed.

Common file error
FileNotFoundError: [Errno 2] No such file or directory: '.../sample_data.json'

Check these before rewriting code:

  1. Are resume_analyzer.py and sample_data.json in the same folder?
  2. Is the filename spelled exactly sample_data.json (not sample_data.json.txt)?
  3. Did you save both files before running the script?
  4. Does the terminal error point to the file you actually created?

AI assistant tip: Copy the error message and ask: “Explain this error to a beginner. What is the most likely cause? Give me the smallest check to perform first. Do not rewrite my whole program.” Do not paste real resumes, secrets, or API keys into public tools.

Quick comprehension check

1. Where should you change the fictional candidate's name for this exercise?

2. Why does the loop check SQL even if SQL is absent from Alex's resume?

3. What can our current skill checker conclude?

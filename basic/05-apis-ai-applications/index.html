AI FOUNDATIONS · WEEK 05 · 02/12

LAYERS

The browser, your app, and the provider do different jobs.

If you mix up the layers, you will debug the wrong thing.

WHO OWNS WHAT?
CLIENT
Browser shows inputs and results.
SERVER-SIDE APP
Streamlit runs Python and protects secrets.
PROVIDER
External service receives a request and returns a response.
where should the fix happen?
Question: The page title changed, but the app still says “Unauthorized.”
Frontend text ≠ API credential

The visual layer cannot repair a server-side key problem.

First ask: is this a UI problem, an app-logic problem, or a provider problem?

AI FOUNDATIONS · WEEK 05 · 03/12

API

An API is a contract between pieces of software.

Not the model itself. Not the webpage. The connection.

request / response
POST /analyze
{
  "resume": "Built Python reports",
  "job": "Python required"
}

→

{
  "supported": ["Python"],
  "missing_evidence": [],
  "suggestions": ["Show project impact"]
}
THINK LIKE A SERVICE
You send a request in a supported format. The service returns a result—or an error.
WHY IT MATTERS
Network access, credentials, cost, and latency all appear here.

AI FOUNDATIONS · WEEK 05 · 04/12

HTTP

Status codes tell you where to look next.

They are clues, not complete diagnoses.

200s
Succeeded

The service accepted the request and returned a response.

400s
Client issue

Bad request, invalid input, or unauthorized key.

500s
Server issue

The provider had a problem on its side.

If the server is unreachable, rewriting your prompt will not fix the outage.

AI FOUNDATIONS · WEEK 05 · 05/12

STRUCTURE

JSON makes output testable.

A nice paragraph is harder to trust than a structured contract.

TARGET SHAPE
{
  "supported": ["Python"],
  "missing_evidence": ["stakeholder communication"],
  "suggestions": ["Add a project example"],
  "limitations": "Text-only analysis"
}
PARSE
Can the app read the response as valid JSON?
CHECK TYPES
Are these fields actually lists and strings?
VALIDATE
Do the claims stay grounded in the resume text?

AI FOUNDATIONS · WEEK 05 · 06/12

SECURITY

API keys belong in runtime secrets, not public code.

A secret in your repo is no longer a secret.

UNSAFE
model_provider.py
API_KEY = "sk-live-..."
client = Provider(api_key=API_KEY)
Problems:

Copied into Git history • visible in screenshots • easy to leak

SAFE PATTERN
Secret store
.env or platform settings
→
Server-side read
os.environ[...]
→
Authorized request
never shown to browser
If a key leaks, rotate it. Deleting the latest line is not enough.

AI FOUNDATIONS · WEEK 05 · 08/12

MODEL USE

Add the model for language—but keep your baseline and boundaries.

The model should enhance the experience, not replace your judgment.

1BaselineDeterministic evidence check
2PromptAsk for grounded suggestions only
3ValidateParse JSON + inspect claims
4FallbackShow baseline if model fails
5DisplayMark limits clearly
Good prompt: “Suggest clearer phrasing based only on resume evidence.” Bad prompt: “Improve this resume however you want.”

AI FOUNDATIONS · WEEK 05 · 09/12

ROBUSTNESS

Failure states are part of the product.

A professional app explains what happened and still helps the user.

MISSING KEY
No live model

Show baseline analysis and a clear note that AI enhancement is unavailable.

TIMEOUT
Slow provider

Tell the user the external service did not respond in time.

BAD JSON
Malformed response

Reject the untrusted output instead of crashing or pretending it is valid.

“Could not enrich with the model. Here is the verified baseline result.”

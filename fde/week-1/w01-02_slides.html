The Investigation

01-02

Discovery is not a sales pitch.

Many enterprise AI projects start to fail during problem definition, long before implementation begins.

  • Customers rarely describe their real constraint. They describe a symptom, a desired solution, or a vague outcome.
  • The FDE must work backward from that description to the actual workflow problem.
The moment the FDE starts proposing architecture in a discovery session, the session stops being an investigation and starts being a pitch. The Golden Rule of Discovery

Stakeholders

01-02

Who belongs in the room?

If only two of these three are available, note what is missing and plan a targeted follow-up.

Executive Sponsor
Owns the problem and controls the budget. They anchor the conversation to real organizational priorities that will actually get funded.
Ops / Domain Expert
Performs the actual work today. They know where the workflow breaks and describe the system as it actually runs, not how it was designed.
Technical Contact
Knows which systems are involved, where data lives, and what access looks like. Essential for evaluating technical feasibility.

Execution

01-02

How to run the session

1. Ask about the Workaround

  • Ask what the team actually does when the official process breaks down.
  • The workaround is often the clearest signal of where the real operational pain lies.

2. The 5-Column Note Framework

  • Capture every observation into five specific columns: stated pain, current workflow steps, data available, candidate success metric, and blockers.

3. Listen for Signals

  • Data signals: System names, file types, data sources.
  • Volume/Frequency: Converts vague pain into a measurable baseline.
  • Ownership gaps: When no one owns a step, it is a massive project risk.

4. The Readback

  • Before leaving, summarize the core problem, data, and success metric out loud. Misalignments surface immediately.

Validation

01-02

Is it actually an AI problem?

Not every workflow problem needs AI. Look for these four signals:

Document-Heavy Synthesis
Tasks involving reading, summarizing, or extracting across large volumes of contracts or policy documents.
Knowledge Retrieval at Scale
Answering questions from large internal knowledge bases or routing inputs based on content.
Multi-Step Workflows
Dependent steps with conditional decisions where agentic systems can orchestrate the task end-to-end.
Repetitive Judgment
Consistent decision patterns (classification, routing) where the value of automation scales with volume.

Failure Modes

01-02

What goes wrong in discovery

  • Solutioning too early: Proposing architecture closes down the investigation.
  • The HiPPO problem: The "Highest-Paid Person's Opinion" dominates over the actual operational pain.
  • Discovery theater: Asking surface-level questions and leaving without a clear picture of constraints.
  • Scope Creep: Customers add requirements in real time. Close the session with a summary, not an open invitation.
Skipping the baseline: Scoping an AI solution without knowing what the current process costs in time, error rate, and token cost makes it impossible to build a credible business case. The Fatal Flaw

The Artifact

01-02

What a scope document does

It is a shared agreement for a 2-4 week Proof of Concept. It must contain these 6 elements:

01   Problem Statement
1-2 sentences describing the specific workflow problem written in the customer's own language.
02   Success Metric
A specific, measurable criterion (precision rate, processing speed) tested before the demo.
03   Data Sources
What data the system reads from, where it lives, and who controls access to it.
04   Tech Dependencies
Internal APIs, data storage, auth services, and the specific external model APIs required.
05   Out of Scope
Load-bearing. An explicit list of what will not be built to defend against scope creep.
06   Timeline
The specific date by which something demonstrable will be ready.

Translation

01-02

The 5-Level Translation Ladder

This framework narrows a broad business problem into the Minimal AI Component.

  • 1. Business Pain: Legal team review bottleneck delays vendor onboarding by days.
  • 2. User Workflow: Lawyer reads PDF, checks standard terms, routes for approval.
  • 3. Data Flow: Contracts arrive by email as PDFs. Standard terms live in a shared drive.
  • 4. System Integration: Solution needs to interact with email inbox, document storage, and approvals.
  • 5. Minimal AI Component: A system that extracts clauses and produces a deviation report. (Routing and email integration remain manual for version one to target the highest-effort step first.)

Architecture Selection

01-02

Selecting the Architecture

If data is unclear, run a 1-2 day Scoping Spike before committing. Then, match the architecture to the problem signal:

Structured LLM Extraction / RAG
Best for large volumes of documents requiring extraction, comparison, or summarization.
RAG with Semantic Retrieval
Best when questions must be answered from a large internal knowledge base.
Agentic Workflow w/ Tools
Best for multi-step processes with conditional routing and handoffs between systems.
Enterprise Integration Context
Model choice must account for integrations with email, Slack, CRM, ERP, or SharePoint.

The Constraint

01-02

The Token Budget Constraint

Token budget is a real constraint that shapes the architecture decision.

  • Agentic workflows with many tool calls and long context windows carry the highest token cost per transaction.
  • RAG reduces cost by sending only the most relevant context to the model.
  • Structured extraction calls can be batched and optimized.
A system that works at POC scale but becomes financially unsustainable at production volume is a risk that belongs in the scope document, not a surprise that surfaces after launch.

Risk Management

01-02

The Technical Risk Register

Capture the risk, likelihood, impact, and mitigation plan. Presenting risks early builds trust.

Data Quality
Enterprise data is frequently inconsistent, incomplete, or structured differently than described.
Access Delays
IT security reviews for internal API access or credentials routinely take longer than estimated.
Model Performance Gaps
Base models underperform on narrow, specialized legal or medical language missing from training data.
Latency & Throughput
Acceptable speed on a small test set may fail against infrastructure constraints at daily volume.

The No-Win Scenario

If a project has no realistic path to a demonstrable result given the data, access, and architectural constraints, the right decision is to pause before committing.

Walking away before starting is more professional than stalling mid-build.

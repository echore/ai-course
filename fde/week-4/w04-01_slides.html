Module 04-01 · AI Forward Deployed Engineer

From harness to system

04-01

Multiple agents add a coordination layer

Each agent has a bounded role

  • Instructions, task context, tool access, and operating limits.
  • Agents can share model providers and infrastructure.

Coordination connects the work

  • Assign tasks and validate returned results.
  • Move state across boundaries and decide when to continue.

The customer inherits both

  • Failures within an agent and failures between agents.
  • Ownership of traces, recovery, configuration, and cost.
More agents create more boundaries to define, test, and operate.

Architecture decision

04-01

Use multiple agents when the work justifies them

Independent workstreams

Parallel tasks can reduce completion time when they do not depend on each other.

Distinct capabilities

Different tool scopes or specialist instructions make responsibility boundaries useful.

Context separation

Delegate bounded tasks with focused evidence instead of carrying every detail in one session.

Test the simpler baseline

A single agent or deterministic workflow may already satisfy the requirement.

Validate the benefit

Compare quality, latency, coordination overhead, and customer maintenance effort.

Decompose responsibilities first. A separate responsibility does not automatically require a separate agent.

Pattern 1 · dependent stages

04-01

Sequential: pass a validated result forward

Example: turn collected evidence into a reviewed report.

Research

Collect relevant information and preserve sources.

→

Analyze

Interpret the evidence against the task.

→

Draft

Produce the agreed output from the analysis.

Why it fits

Each transformation depends on the previous stage’s result.

What to test

Validate intermediate outputs; stop or recover when a stage fails.

A clear trace shows the earliest stage where the result diverged.

Pattern 2 · fan-out and collection

04-01

Parallel: independent tasks, one combined result

Shared research goal

Assign independent regional coverage.

Americas worker

Research the assigned region.

Europe worker

Research the assigned region.

Asia worker

Research the assigned region.

Aggregate the evidence

Combine results with source links and explicit missing-work status.

Set concurrency limits and deadlines. Partial results need a defined handling policy.

Pattern 3 · bounded iteration

04-01

Loop: improve an output within a fixed budget

Produce a candidate

Generate the initial or revised output.

→

Check criteria

Evaluate evidence, completeness, or format.

→

Revise if needed

Use specific feedback for the next attempt.

Success exit

Stop when validated criteria are met.

Budget exit

Stop at the iteration, token, or time ceiling and preserve unresolved work.

A quality target and a hard stopping rule are separate requirements.

Pattern 4 · central planning

04-01

Hierarchical: one coordinator manages workers

Orchestrator

Choose a worker, send the relevant context, and track the overall task.

Research specialist

Gather evidence in its assigned scope.

Analysis specialist

Interpret the supplied evidence.

Drafting specialist

Produce the requested artifact.

Orchestrator receives results

Validate output, update state, and decide the next useful step.

Workers report to the coordinator. Invocation can be sequential or parallel; this diagram shows available roles.

Control transfer

04-01

Handoff: transfer responsibility and task context

Intake agent

Qualify the issue and record completed work.

→

Validate the handoff

Check the receiving role and required payload.

→

Resolution agent

Take over using the validated context.

What transfers

  • Original goal, completed actions, evidence, and unresolved work.
  • Constraints, permissions, and the next responsibility.

What differs from delegation

The receiving agent takes control. The first agent does not keep coordinating the same task.

A failure can surface in the receiver even when its cause is an incomplete handoff.

ConcernDefine before buildingVerify in the pilot
State and contextTask IDs, schemas, evidence references, and current statusReject missing, stale, or unrelated results.

Cost and latency

04-01

Parallelism changes time; total work drives cost

Sequential time

Roughly the sum of dependent stage times, plus coordination overhead.

Parallel time

Roughly the slowest required branch, plus collection and downstream stages.

Per-task cost

Add all model tokens, tools, retries, review calls, and infrastructure work.

Projected volume

Measure representative tasks, then estimate peak concurrency and operating cost.

Parallel execution is not automatically cheaper. Loops and duplicated context can increase work.

From design to implementation

04-01

A framework implements decisions you still own

Framework scaffolding

  • Execution flow, tool conventions, state and memory integration.
  • Persistence, tracing, and review hooks where supported.

FDE design decisions

  • Role boundaries, context contracts, and approval rules.
  • Retry budgets, evaluation criteria, and customer ownership.
Choose against the required behavior and the team’s ability to maintain it.

Framework landscape

04-01

LangChain and LangGraph offer different abstraction levels

LangChain

Model and tool integrations, configurable agent patterns, and middleware.

  • Its agents use LangGraph underneath.
  • Useful when existing abstractions cover the required behavior.

LangGraph

Lower-level stateful orchestration with explicit nodes and transitions.

  • Useful for custom branching, persistence, and human interrupts.
  • Evaluate how easily the team can inspect and change the graph.
Choose the level of control you need; these are related layers, not a strict agent-versus-workflow split.

Framework landscape

04-01

Roles and conversations express coordination differently

CrewAI

Crews express specialist roles and tasks; Flows add stateful execution control.

  • Useful for readable role-based task organization.
  • Test routing, persistence, and failure handling for the required flow.

AutoGen

AgentChat and message-based coordination support conversational teams.

  • Useful context for existing conversational implementations.
  • AutoGen is in maintenance mode; assess Microsoft Agent Framework for a new build.
The expression model and maintenance status both affect the handoff decision.

Framework landscape

04-01

Provider SDKs need a feature-level compatibility check

OpenAI Agents SDK

Agent loops, tools, handoffs, and tracing. Non-OpenAI provider paths are also available.

Verify the features supported by the chosen provider.

Google ADK

Agent and workflow primitives, optimized for Gemini but model- and deployment-agnostic.

Existing Google integrations can reduce setup work; they are not a hosting requirement.

Claude Agent SDK

Claude Code’s agent loop, tools, sessions, permissions, hooks, and subagents.

Check approved model access, runtime controls, and deployment requirements.

Native integration can be useful without implying that every SDK has the same portability or features.

Framework selection

04-01

Evaluate five criteria together

Design fit

Can the required dependencies, loops, control transfers, and state contracts be expressed clearly?

Model and vendor flexibility

Does the selected provider path support the required tools, outputs, hosting, and data policy?

Observability

Can the team correlate runs, inspect failures, and evaluate results without excessive custom work?

Implementation speed

Can the team deliver a representative slice within the sprint and learn the needed abstractions?

Post-handoff ownership

Can the customer change configuration, recover failures, and maintain supported versions?

A useful proof: implement one realistic task with a failed tool call and an approval pause.

Recommendation in practice

04-01

Work with the customer’s existing stack

It fits

Use existing conventions and integrations. Reduce ramp time and avoid unnecessary migration.

It is workable

Deliver within the stack. Document accepted limitations, monitoring, and the maintenance cost.

It blocks the requirement

Show the specific constraint and delivery risk. Compare adapting, switching, and reducing scope.

The customer owns the decision. Support the recommendation with a tested constraint and a clear tradeoff.

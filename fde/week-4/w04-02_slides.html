Illustrative logistics case

04-02

The customer needs faster disruption decisions

45,000 active shipments

Across North America, Europe, and Southeast Asia.

200+ carriers

Weather, port closures, and capacity failures change available routes.

30 regional hubs

Multiple disruptions can overwhelm a coordinator working one event at a time.

Automate gathering, analysis, and packaging; give the coordinator a supported decision to review.

Clarifying questions

04-02

Discovery turns the request into design inputs

Workflow and process

Which signals trigger analysis? What threshold matters? Who approves, and when is manager approval required?

Data and systems

Which route legs, fields, and timestamps exist? How fresh are slots and quotes? Which signals describe the same event?

Risk and authority

What does a wrong reroute cost? Is a missed disruption worse than a false alarm? Which actions must be gated?

Success and scope

Which disruption and shipment types come first? What reduces review effort or missed rerouting windows?

Make thresholds, approval authority, input contracts, and pilot success criteria explicit.

Non-negotiable case requirements

04-02

Three constraints shape the architecture

Approval before SAP writes

  • The company requires an explicit authorized human decision.
  • An open recommendation is not permission to execute.

Filter before ranking

  • Apply the shipment-type approved-carrier list first.
  • Hazardous, cold-chain, and oversized loads have separate constraints.

Isolate concurrent events

  • Keep business context and results scoped to each disruption.
  • One slow or failed chain must not block unrelated work.
These are system boundaries enforced by code, permissions, and state—not instructions in a prompt alone.

System architecture

04-02

Five agents implement the six responsibilities

Detect

Confirmed disruption event.

→

Identify

Affected loads and estimated delays.

→

Options

Ranked, eligible alternatives per load.

→

Recommend

Cost comparison and plain-language package.

→

Execute

Wait for approval; then update and notify.

Combine related work

The recommendation agent owns both cost comparison and packaging. Internal functions perform validated calculations.

Enforce the final boundary

Execution consumes a recorded decision. Analysis agents do not receive production write access.

Structured outputs connect the chain; the recommendation also uses the identification agent’s delay estimates.

Detection agent

04-02

Detection produces one traceable event

Fetch scheduled signals

Weather, port congestion, and carrier exceptions.

→

Normalize and deduplicate

Align schemas; merge signals for the same event.

→

Apply the threshold

Log low-level signals; dispatch confirmed disruptions.

Event contract

Event ID · source references · route/port/carrier · severity · observed time.

Failure handling

Mark unavailable or stale feeds; do not silently treat missing evidence as normal conditions.

Scheduled polling is recurring execution. It is distinct from retrying a failed analysis.

Identification agent

04-02

Shipment impact includes every route leg

A port disruption may affect a shipment even when its origin and final destination are elsewhere.

Origin

Shipment begins here.

→

Transit port

The confirmed disruption affects this leg.

→

Destination

Final delivery inherits the delay.

Input and lookup

Use the confirmed route, port, or carrier to query active SAP TM loads across all relevant legs.

Structured result

Shipment IDs, matching legs, disruption type and severity, and estimated delay per shipment.

Retain the estimated delays: the recommendation stage needs them to compare rerouting with staying put.

Options and contractual constraints

04-02

Eligibility is a filter, not a scoring preference

Retrieve candidates

Available carrier slots, routes, and current quotes.

→

Enforce eligibility

Shipment-type carrier list and mandatory requirements.

→

Rank feasible options

Delivery impact, availability, and relevant tradeoffs.

No eligible option is a valid outcome: explain the constraint and route the shipment for review.

Recommendation agent

04-02

A recommendation compares two real scenarios

Keep the delayed route

  • Affected load and estimated delay from identification.
  • Contractual SLA and delay-cost parameters.
  • Remaining uncertainty and operational consequences.

Take the alternative

  • Eligible route, carrier, slot, and quote validity.
  • Rerouting cost, delivery impact, and feasibility.
  • Evidence supporting the proposed choice.
Package the comparison in plain language. Surface ambiguous or high-authority decisions first for escalation.

Human approval boundary

04-02

Record the decision before taking action

Approve

An authorized decision allows the specified SAP update and carrier notification.

Escalate

Send the package to the manager queue when authority or uncertainty requires it.

Defer

Keep the event open without executing or marking it resolved.

Approval record

Approver identity · timestamp · decision · shipment and recommendation version.

Durable queue

The event and decision survive a service restart or coordinator session change.

Recheck record versions and quote validity before execution. Changed inputs require renewed review.

Execution agent

04-02

Execution returns confirmations and an audit trail

Check approval and freshness

Validate authority, scope, and record version.

→

Update SAP TM

Apply the approved rerouting action.

→

Notify and record

Send the carrier notice; save outcome status.

Safe recovery

Use idempotency or equivalent duplicate protection. Reconcile an uncertain write before retrying.

Partial failure

If SAP succeeds but notification fails, preserve both statuses and retry only the outstanding action.

Every write must link to its approval identity, timestamp, plan, and execution result.

Orchestration layer

04-02

Combine three execution patterns deliberately

Scheduled detection

Fresh polling cycles create confirmed events; polling is not a quality-improvement loop.

Sequential backbone

Detect → identify → options → recommend → approved execution. Each stage needs a valid result.

Parallel work

Independent event chains, plus per-load option workers inside each event.

Isolate event business state, while sharing infrastructure. Overlapping shipments still need conflict checks before writes.

MCP and A2A

04-02

Protocols connect interfaces; the runtime manages work

MCP: tools and resources

Model Context Protocol standardizes access to external capabilities.

  • Expose typed integration interfaces where useful.
  • Configure authentication, authorization, and tool-level traces.

A2A: agent interoperability

Agent-to-Agent connects agents through task and message interfaces.

  • Useful across separately implemented agent services.
  • The runtime still owns worker creation, state, and concurrency.
Both are optional architecture choices. Direct SDK calls and framework-local delegation can serve a single-system pilot.

Evaluation plan

04-02

Evaluate decisions, boundaries, and operating effort

Detection precision and recall

Use labeled historical events across the three feeds.

  • Precision: how many triggered events were real?
  • Recall: how many relevant real events were caught?

Recommendation quality

Compare options with coordinator criteria and feasible alternatives.

  • Check eligibility, costs, explanations, and uncertainty.
  • Add rejected recommendations to the evaluation set.

Audit completeness

Every SAP write has a complete matching approval record.

  • Missing identity, time, or approved-plan evidence is a failure.
  • Test denied and deferred decisions too.
Also measure time to recommendation, model/tool cost, queue age, and coordinator review burden.

FDE delivery and handoff

04-02

Prove one complete slice before expanding

Scope a useful pilot

Choose one high-impact disruption type, agreed shipment categories, and a bounded load volume.

Exercise the boundaries

Test duplicate signals, stale quotes, no eligible carrier, denied approval, overlapping events, and partial execution.

Transfer ownership

Hand off contracts, thresholds, evaluation cases, approval configuration, dashboards, and recovery runbooks.

Success means a supported decision and an auditable action that the customer can operate.

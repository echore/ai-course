Q01 · Retrieval design

03-02

When would you choose hybrid search?

Choose it when the query distribution includes both semantic questions and exact-term lookups.

Dense retrieval

Embed the question and search document vectors for related meaning, even when wording differs.

Example: sector trends described with different vocabulary.

Sparse retrieval

Use BM25 keyword ranking based on term statistics.

Example: a specific ticker, deal name, or regulatory citation.

Rank fusion

Combine both ranked lists. Reciprocal Rank Fusion sums 1/(k + rank) contributions; k is a smoothing constant.

This avoids directly adding incompatible score scales.

Validate the gain across query categories and measure the added retrieval work. Apply permissions to both branches.

Q02 · Retrieval design

03-02

Why use a cross-encoder as the reranker?

Bi-encoder: efficient first pass

  • Encode documents and queries independently.
  • Precompute document vectors and reuse them.
  • Search a large corpus quickly, but similarity can miss fine-grained question–passage interactions.

Cross-encoder: targeted relevance scoring

  • Process each question and candidate passage jointly.
  • Score their interaction for the specific question.
  • Use it on a small candidate set; scoring the entire corpus per query would be expensive.
Reranking trades extra query-time compute for a potentially better final selection. Verify the gain and latency.

Q03 · Context selection

03-02

20 candidates, room for 5: what changes?

Retrieve 20

Keep enough authorized candidates to support recall.

→

Rerank & deduplicate

Score relevance and remove redundant evidence.

→

Select within budget

Choose useful passages while reserving tokens for instructions and output.

Select evidence deliberately

Consider relevance, diversity, and coverage of multi-document questions. Five near-duplicate passages may omit an important requirement.

Do not shrink chunks blindly

Smaller chunks can fit more results, but may lose meaning. Test boundary effects and answer completeness.

Budget in tokens, not only chunk count. Reranking improves selection; it does not enlarge the context window.

Q04 · Chunking design

03-02

How does parent–child chunking help?

Match a child

Retrieve a small paragraph with precise content.

→

Expand to its parent

Load the surrounding section for interpretation.

→

Select context

Deduplicate parents, verify access, and fit the budget.

Benefit

Separates the unit used for retrieval from the unit supplied as context. Small children improve focus; parents restore surrounding meaning.

Tradeoff

Parent expansion can increase tokens and redundancy. Preserve parent IDs, document versions, permissions, and source locations.

Bank example: retrieve a policy paragraph, then include its section heading and relevant qualifications.

Q05 · Query transformation

03-02

How does HyDE work, and what is the tradeoff?

HyDE means Hypothetical Document Embeddings: generate a hypothetical passage to help retrieve real evidence.

Question

The user describes an information need.

→

Hypothetical passage

A local model generates document-like text.

→

Embed & retrieve

Encode that text and search the authorized corpus.

→

Answer from sources

Use the real retrieved passages, not the hypothetical text.

Potential benefit: bridge vocabulary gaps. Costs: an extra model call, latency, and possible query drift. Test before enabling it.

Q07 · Unsupported claims

03-02

High context precision, low faithfulness: what next?

Relevant evidence was selected, yet the response contains claims that the evidence does not support.

Inspect and correct generation

  • Compare each failing claim with the actual model context.
  • Constrain answers to available evidence and permit abstention.
  • Check citations and unsupported synthesis; evaluate prompt or model changes.

Measure the improvement

  • Group failures by query type and source.
  • Use a validated local judge to assist review.
  • Retest with reference cases and expert checks; do not treat a prompt change as proof of a fix.
Relevant context can still be incomplete. Confirm evidence coverage before attributing every failure to the model.

Q08 · Missing evidence

03-02

High precision, low recall: which questions suffer?

What the metric pattern means

Returned evidence is relevant, but other needed evidence is missing.

Distributed answers are vulnerable: one precise passage may omit conditions found in another policy or document.

How to investigate

  • Expand the candidate pool before reranking and test coverage.
  • Check chunk boundaries, source coverage, and stale indexes.
  • Tune dense, keyword, or query-transformation behavior according to the missed query pattern.
More candidates can improve recall but add cost. Keep the final context focused and measure answer completeness.

Q09 · Enterprise access control

03-02

How can indexed permissions avoid repeated source lookups?

Index effective ACLs

Store each document’s access metadata on its chunks.

→

Resolve current identity

Use authenticated user and group information.

→

Filter every search

Only authorized evidence becomes a candidate.

→

Maintain freshness

Sync changes and enforce a revocation policy.

Benefit

Avoid many per-document source permission calls on the ordinary query path.

Required qualification

Authorization is still enforced at query time. Filtering has cost; scheduled sync can leave stale access. Verify freshness or fail closed when necessary.

Account for inherited and direct access, cache isolation, and revocation. Index-time metadata is not the entire security decision.

Q10 · Versions and disagreement

03-02

How should contradictory documents be handled?

Version conflict

  • Preserve lineage, effective dates, and source authority.
  • Flag superseded versions during ingestion.
  • Do not assume the newest timestamp always means the authoritative policy.

Genuine disagreement

  • Present the conflicting claims with their citations.
  • State the limits of the available evidence.
  • Route consequential unresolved cases to the named expert instead of inventing consensus.
Transparency comes first. Differentiate outdated copies from legitimate analytical disagreement.

Q11 · Architecture assumptions

03-02

Does a million-token window remove the need for RAG?

What long context can help

Include more authorized evidence, larger sections, or several related documents.

For a bounded task, directly supplying a small document set may be a reasonable baseline.

What it does not solve

  • A growing enterprise corpus can still exceed the window.
  • Repeatedly sending large inputs adds latency and cost.
  • Freshness, access control, and evidence selection remain design responsibilities.
Choose long context, retrieval, or both from measured task behavior. Long context does not automatically enforce permissions.

Q12 · New language requirement

03-02

Mandarin questions, English documents: what changes?

Dense retrieval & migration

  • Test a multilingual encoder such as multilingual-E5.
  • Re-embed the corpus in the new compatible space and plan a controlled index migration.
  • Evaluate Mandarin queries against English evidence.

Keyword search & generation

  • English BM25 will not directly match Mandarin wording.
  • Test query translation or language-aware routing and fusion.
  • Validate the generator’s Mandarin output and citations.

What remains, what is retested

  • Preserve permission and source-connector design.
  • Recheck encoder input limits and context selection.
  • Keep translation and model calls private.
A multilingual model is a candidate, not proof of quality. Measure cross-lingual retrieval and answer performance.

Q13 · New compliance requirement

03-02

How would you add an abstention and human-review gate?

Evidence gate

Check calibrated retrieval and coverage signals.

→

Answer review

Evaluate grounded claims and required completeness.

→

Deliver or abstain

Allow validated cases; use a clear fallback for unresolved ones.

→

Expert queue

Send evidence, routing reason, and task context to a named owner.

Calibrate thresholds by user group. Raw similarity and model self-confidence are not probabilities of correctness.

Q14 · FDE scoping

03-02

What belongs in a two-week POC?

Prove the hardest unknowns

  • Retrieval quality on real bank documents.
  • Correct permission filtering across user groups.
  • One complete ingestion-to-citation path.

Constrain the scope

  • One approved source and representative document libraries.
  • A small question set and explicit permission tests.
  • Defer email/file-server connectors, OCR, and the full operational build.

Make the result actionable

  • Agree quality, latency, and access criteria.
  • Record data and compute dependencies.
  • Demo findings and recommend proceed, pivot, or stop.
Cut the full evaluation platform, not basic evaluation. A POC must produce evidence against agreed success criteria.

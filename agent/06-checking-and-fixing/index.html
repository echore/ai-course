Module 6 · Checking and Fixing

Rule 1 · Check Against a List

Turn the requirements into checks.

Save CHECKLIST.md in your project folder. Each item says what must be true and what to compare it with.

At each delivery: ask the agent to read the checklist, run saved checks and show evidence. Saving the file does not run it.

Sources: Matt Pocock: Standards; pstack: Prove It Works and Verification. Anthropic: Best practices. Course adaptation.

Module 6 · Checking and Fixing

Rule 2 · Get a Second Look

Open a fresh conversation to check the work.

Provide the requirements, result, checklist and original sources.

Ask for evidence. Allow “all pass” or “unable to check”. A second opinion can be wrong too.

Sources: Anthropic: Best practices; pstack: Interrogate; OpenAI: Codex CLI.

Module 6 · Checking and Fixing

Rule 3 · Fix the Cause

Show the failure before asking for a fix.

Expected: what should happen. Got: what happened. Evidence: what shows the difference.

Ask where the first wrong step occurred. Confirm the explanation using data or actual actions.

Sources: pstack: Fix Root Causes, Bug Fix, and Verification; Anthropic: Best practices.

Module 6 · Checking and Fixing

Rule 3 · Fix the Cause

Fix the cause, then check again.

In this example, inspecting the calculation confirms that it never subtracted returns.

Recheck every region in both weeks, then the other requirements. Keep the checklist just as strict.

Sources: pstack: Fix Root Causes, Bug Fix, and Verification; Anthropic: Best practices.

Module 6 · Checking and Fixing

Rule 4 · Add It to the List

The check must cover the whole report.

Next week, West is wrong. The checklist said “every region,” but the saved check only tested East.

Strengthen the saved check and update the checklist. Save both, then ask the agent to run them at each delivery.

Sources: pstack: Correct. Course adaptation.

Module 6 · Checking and Fixing

Rule 4 · Add It to the List

Prove that the improved check catches the mistake.

Keep a wrong version. The same check must reject it and accept the corrected version.

Rule 3 repairs the current result. Rule 4 improves the check you will reuse next time.

Sources: pstack: Correct. Course adaptation.

Takeaway

Use these four rules before you accept “done”.

1
Check against a list

Compare the result with the requirements and sources.

2
Get a second look

Give a fresh conversation the files it needs to check.

3
Fix the cause

Confirm the cause, fix it, then check again.

4
Add it to the list

Improve and save the check for next time.
